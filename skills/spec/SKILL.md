# 機能仕様

ユーザーの要求を `specs/<feature>/spec.md` へ整理する。

開始前に `hooks.yml` の `before_spec`、完了前に `after_spec` を処理する。

## 手順

1. 既存仕様、README、コード、ADRを確認する。
2. 対象ユーザー、主経路、状態遷移、入出力を特定する。
3. 曖昧な点は影響の大きい順に最大3件だけ質問する。
4. 機能要件をテスト可能な表現にする。
5. 性能、互換性、対応環境、アクセシビリティを必要に応じて定義する。
6. スコープ外、仮定、未決事項を明示する。
7. `templates/spec-template.md` の順序で書き出す。

## 完了条件

- 実装技術を仕様へ混ぜていない
- すべての要件に受け入れ条件がある
- 主経路と異常系を説明している
- 成功条件が測定可能
- 未決事項が3件以内
