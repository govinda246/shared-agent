# 設計

`spec.md` を読み、`design.md` と必要なADRを作成する。

開始前に `hooks.yml` の `before_design`、完了前に `after_design` を処理する。

## 手順

1. ドメイン、状態遷移、入力、UI、外部連携の責務を整理する。
2. データモデルとイベント境界を定義する。
3. 初期化順、キャンセル、再起動、破棄処理を確認する。
4. ADR候補を洗い出し、選択肢・根拠・影響・再検討条件を書く。
5. 性能予算と検証方法を設計する。
6. プロトタイプが必要なら仮説と最短の検証内容を示す。

## ADRを必須にする例

- ライフサイクルや状態所有の変更
- 並列処理、時間処理、同期方式の選択
- 公開APIやホスト連携方式
- ネットワーク同期・キャッシュ・権威モデル
- 永続化形式
- ドメイン固有のアセットまたはデータパイプライン

`templates/adr-template.md` を使用する。
