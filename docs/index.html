Shared Agent Guide

ゲーム開発を、安く、堅く、追跡可能に。

Shared Game Agent は、Copilot の呼び出し回数ではなく、 1タスクを正しく完了するまでの総コストを下げるための運用パックです。

構成を見る 判断方法 導入手順 GitHub

最初に守る3つのこと

安価なモデルへ細切れ委任するより、無駄な再読込と再試行を減らします。

01 Direct first

軽い作業は直接処理

短い検索、短い要約、数行の修正、既読ファイルの変更は委任しません。

02 Packet based

受け渡しを小さくする

会話履歴ではなく、対象範囲、受け入れ条件、検証をTask Packetで渡します。

03 Risk gated

危険な判断だけ独立レビュー

状態、時間、Scene、入力、同期、性能の高リスク変更だけ分離します。

Agent 構成

Conductor が唯一の窓口です。仕様の曖昧さと失敗時影響に応じて、 直接処理・Worker・独立レビューを選びます。

どこへ委任するか

ファイル数ではなく、曖昧さと失敗したときの影響で決めます。

受け入れ条件が明確 対象範囲、入出力、検証方法、禁止事項をTask Packetへ書ける。
+
出力が十分にまとまる 実装量が、親から子への読込と結果確認を上回る。

どちらか一方でも満たさない場合は、Direct を優先します。 仕様や設計が未確定なら Worker へ渡さず、Conductor または Architect で判断します。

Direct

低コスト・低不確実性

  • 数行から数十行の修正
  • 短い検索や参照確認
  • 親がすでに読んだファイル
  • 委任準備より直接作業が短い
Implementer

低不確実性・まとまった出力

  • 承認済み仕様とADR
  • 編集可能ファイルが限定済み
  • 対象テストが明確
  • 1機能または1タスク分の作業
Verifier

再現可能な証拠収集

  • テスト、build、typecheck、lint
  • 仕様IDと実装・テストの対応
  • ブラウザー・入力の確認状況
  • 手動確認を推測で合格にしない
Independent Review

高リスク・独立した第二判断

  • Scene、状態所有、状態遷移
  • 時間、入力、同期、永続化
  • アセット失敗、性能、メモリ
  • ADRや再検討条件が必要

Task Packet

会話履歴全体ではなく、必要な契約だけを実装担当へ渡します。

タスクID: HUD-003
完了条件: 敵HP変化がHUDに反映され、0でバーが消える
受け入れ条件: AC-12, AC-13
編集可能: src/ui/Hud.ts, test/Hud.test.ts
参照: specs/hud/spec.md#AC-12, design.md#event-boundary
検証: npm test -- Hud.test.ts; npm run typecheck
禁止: Combat stateの変更、外部依存追加
試行上限: 2
差し戻し: 入力仕様や状態所有の判断が必要になった場合

無限ループを止める差し戻し

Escalate

すぐ親へ戻す

  • 同じ失敗が2回続いた
  • 新しい証拠や仮説が出ない
  • 編集対象外へ波及する
  • 仕様・ADRの不足が見つかった
Complete

報告して閉じる

  • 対象テストが合格した
  • 差分がTask Packet内に収まった
  • 受け入れ条件へ対応できた
  • 未実施の手動確認を明記した

Hook で品質を固定する

工程を飛ばさず、必須ゲートを失敗したまま次へ進みません。

工程 開始前 完了時
仕様 プロジェクト文脈 スコープと受け入れ条件レビュー
設計 技術・セキュリティ制約 ADRレビュー
計画 承認済み仕様・設計 追跡・依存関係・検証ゲート
実装 Preflight 仕様・テスト・ブラウザー検証
検証 対象端末・性能予算（任意） 証拠と未実施項目レビュー

導入手順

1

共有パックを追加

親プロジェクトの .github/shared へ固定commitで追加します。

2

検索対象を設定

.github/shared/agents と skills を検索対象にします。

3

固有Hookを追加

共有Hookを変更せず、親の .github/hooks.yml へ追加します。

4

モデルを設定

Direct、Implementer、独立レビューへ利用環境が対応するモデルを割り当てます。

5

代表タスクで測定

総トークン、再試行、完了時間、品質、人手介入量を比較します。

モデルは「設定」で切り替える

モデル名、倍率、料金、期間は共有Agentの恒久仕様にしません。 利用環境の機能を確認し、実測結果に基づいて親プロジェクト側で設定します。

実際の選択

指定モデルを確認

意図したAgent経路とモデルが実際に使われたかを記録します。

総コスト

1タスク単位で測る

親と子の入出力、再試行、検証まで含めた完了コストで比較します。

品質

合格品質も測る

テスト、仕様追跡、人手修正、差し戻し回数を合わせて判断します。
